## Findings and classification

1. **HDMR measure mismatch: real implementation failure.** `estimate_hdmr` chooses Hermite for Normal and Legendre for every other bounded distribution. Its affine support transformation leaves a triangular or Beta density nonuniform. The coefficient variance weights then refer to a different input measure. Example: independent `X0 ~ Uniform[-1,1]`, `X1 ~ Triangular[-1,1; mode=0]`, `Y=X0+X1`. The model is exactly linear. Its variances are `1/3` and `1/6`, so the correct indices are `(2/3,1/3)` and variance `1/2`. The implementation assigns both linear terms Legendre norm squared `1/3`, yielding indices `(1/2,1/2)` and variance `2/3`. This is not sampling or truncation error. Run `python3 scripts/check-hdmr-literature.py`; it also checks the Uniform/Uniform control. The script exits 1 on the defect, not a false success for reproducing a known bug. Correct documentation now restricts interpretation to independent Uniform/Normal factors. Fixing accepted distributions or mapping requires a separate implementation decision.

2. **PCE coefficient identity: documentation overclaim and wrong equation references.** The formulas calculate the fitted polynomial's indices exactly in exact arithmetic. They do not remove truncation error against the original function. State independence, matching probability measures, and surrogate error. Replace “Sudret 2008 Eq36–39” by §5.4, Eqs. 51 and 53. “All sensitivity information” also overstates what these variance summaries provide.

3. **Jacobi/Beta convention: documentation bug.** For `ξ=2u−1`, the implemented weight `(1−ξ)^alpha (1+ξ)^beta` corresponds to `u ~ Beta(beta+1,alpha+1)`. Therefore `Beta(a,b)` needs `Jacobi { alpha:b−1,beta:a−1 }`. Existing docs reversed the shapes. The polynomial recurrence itself follows the usual Jacobi convention. Also the constant basis function has norm squared one but variance zero; the norm-as-variance claim applies only to positive degree. Updated source docs.

4. **HDMR `max_order`: documentation bug.** This argument limits only `order_variance` length. All interactions permitted by `max_degree` remain fitted; all enter the total variance and total-order indices, and pairwise results are computed even when `max_order < 2`. Reported order fractions can sum below one. Calling it truncation, without qualification, is wrong. The actual routine is a full PCE regression followed by ANOVA coefficient grouping; do not imply it reproduces every RS-HDMR algorithm in Li et al.

5. **Sparse fit: algorithm distinctions and implementation departures.** The implementation is a fixed candidate-basis fit, not the full adaptive Blatman–Sudret algorithm. It uses uncorrected, unnormalized PRESS; retains the best visited fit; and stops after three steps without improvement. The article's `q=0.75` illustration does not establish a universal recommendation. Smaller q can discard important interactions. Remove unsupported recommendation/default claims.

6. **LARS standardization: real algorithm mismatch, effect not numerically quantified here.** Efron Eq. 1.1 centers both predictors and response before column normalization. `lars_forward_select` centers only y and normalizes uncentered polynomial columns. Population orthogonality does not make finite-sample column means zero. Subsequent OLS refits have an intercept, but that does not repair the selected path's geometry. Source docs now state the difference. A centered-predictor oracle should precede a fix.

7. **OMP column scoring: implementation choice.** It selects raw absolute inner products without column normalization. Calling these simply “correlations” hides scale dependence. This matters because polynomial columns have different norms. The documentation now describes raw scores; no universal recovery or robustness claim is justified.

8. **PRESS singular rows: real diagnostic departure.** `loo_error_from_hat` drops rows with `abs(1-h_ii)<1e-10` and averages only the retained rows. Earlier docs said it bailed out. The returned score is not full leave-one-out error when any rows are removed, and it is not cross-validation of the full selection pipeline. This can make selection appear better than its held-out behavior. No numerical failing fixture was added for this branch in this pass.

9. **Active subspace gap: documentation overclaim plus a sampling limitation.** The paper's conditional-mean approximation bound uses a constant times the sum of discarded eigenvalues. A large ratio alone does not bound prediction error. The ratio selector and `1e-12` numerical-rank tolerance are local heuristics, not “Constantine's default.” If `M<d`, the sample matrix necessarily has rank at most M; a numerical zero can reflect too few samples. Gradient coordinates/scaling and sampling distribution must be specified. A single nonzero gradient identifies a true ridge direction; a zero gradient does not. Source docs corrected.

10. **Complexity: documentation error.** Full normal-equation fitting costs `O(NP²+P³)`, not `O(NP+P³)`. Sparse per-step refits and leverage calculations add `O(Nk²+k³)` to the `O(NP)` scan. Both paths allocate the candidate basis matrix. Constructing it entails `O(NPd)` polynomial calls, each with degree-dependent cost up to `O(p)`; do not present polynomial-call count as a degree-independent flop count. Hyperbolic enumeration first generates the full total-degree basis and filters it, with dimension-dependent work.
